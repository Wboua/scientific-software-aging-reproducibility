# Scientific Software Aging — Replication Package

This repository contains the data, evidence records, analysis scripts, generated tables/figures, and manuscript sources supporting the study:

**What Breaks When Scientific Software Ages? An Empirical Study of Long-Term Reproducibility, Repairability, and Fidelity**

Authors: Walid BOUARIFI, Mouad BANA, Soufiane KHIRI.

## Scope

The study revisits ten published scientific-software artifacts (PS001–PS010) across Python/PyTorch, Java/JMH, C/C++, CUDA/HPC, VM-based workflows, and R. Cases are evaluated using a layered capability model covering availability (A), installability (I), buildability (B), executability (E), scientific-result fidelity (N), and performance fidelity (P). Hardware/infrastructure eligibility (H), bounded repair depth (RL0–RL4), recovery status, failure mechanisms, and claim-level provenance are recorded separately.

The corpus is a purposive maximum-variation multiple-case corpus. Reported percentages describe this corpus only; they are not population prevalence estimates.

## Repository layout

```text
analysis/scripts/        Reproducible normalization, analysis, and figure scripts
analysis/                Case annotations, publication metadata, and analysis scripts
data/                    Literature matrix and supporting metadata
docs/                    Study protocol, metrics, taxonomies, and provenance policy
evidence/PS001-PS010/    Case-level metadata, logs, outputs, interventions, and hashes
results/figures/         Generated analysis figures
supplementary/           Claim-to-evidence traceability table
manuscript/              LaTeX source, bibliography, figures, and compiled manuscript
scripts/                 Repository and evidence-integrity utilities
```

Third-party project source trees are not redistributed here. Exact project identities, paper references, repositories, commits where retained, and case-specific reconstruction details are recorded in the evidence metadata and source registry.

## Quick start

Python 3.12 is recommended.

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

python scripts/validate_repository.py
python scripts/verify_evidence_hashes.py
python analysis/scripts/run_analysis.py
python analysis/scripts/robustness_analysis.py
```

The main generated outputs are written to `results/normalized/`, `results/tables/`, and `results/figures/`. Conceptual manuscript diagrams are supplied with the manuscript source; data-driven figures are regenerated by the analysis scripts.


## Evidence integrity

Each case contains a SHA-256 manifest covering retained files under `raw/`, `outputs/`, `environment/`, and `interventions/`.

Regenerate manifests:

```bash
python scripts/generate_evidence_hashes.py
```

Verify them:

```bash
python scripts/verify_evidence_hashes.py
```

`UNKNOWN` and `N/A` are preserved explicitly. Missing historical evidence is not converted into a failure, and author-reported values are distinguished from observations made in this study.

## Data provenance

The master claim registry is `evidence/CLAIM_REGISTRY_MASTER.csv`. The supplementary traceability table links claims to retained evidence. Raw logs are preserved as text/CSV/JSON where available, and intervention records are stored separately from scientific outcomes.
